1. Pythonプロジェクトの最小構成を作る
2. FastAPIアプリケーションを作る
3. `GET /health` を追加する

詳細なコマンドとコードは、M0-C1開始時にCodexが提示する。

# M0-C2: PostgreSQLとバックエンドの疎通

## 成果

PostgreSQLを起動し、FastAPIのhealth APIからDB接続状態を確認できる。

## 学習目的

HTTP通信とDB接続が別の依存関係であることを理解し、DB停止時の失敗をバックエンド側で検出する。

## なぜこの順序か

バックエンド単体の正常動作を確認済みにしてからDBを追加することで、接続失敗の原因をDB側へ限定しやすくするため。

## 主な変更対象

| 領域 | 役割 |
|---|---|
| Docker Compose | PostgreSQLの起動条件を定義する |
| 環境変数 | DB接続情報をコードから分離する |
| DB接続処理 | PostgreSQLへ接続して単純なSQLを実行する |
| health API | backendとdatabaseの状態を返す |
| テスト | DB接続成功・失敗を確認する |

## 実装の大まかな流れ

1. Docker ComposeへPostgreSQLを定義する
2. `.env.example` にダミーの接続設定を追加する
3. PostgreSQLを起動する
4. `psql` で直接疎通を確認する
5. FastAPIから `SELECT 1` を実行する
6. health APIへDB状態を追加する
7. DB停止時の応答を確認する

## 受け入れ条件

- [ ] PostgreSQLを起動・停止できる
- [ ] `psql` から `SELECT 1` を実行できる
- [ ] バックエンドから `SELECT 1` を実行できる
- [ ] health APIに `database: "ok"` が含まれる
- [ ] DB停止時にHTTP応答または状態表示で異常を確認できる
- [ ] 接続情報がソースコードへ直書きされていない

## 異常系確認

- [ ] PostgreSQL停止時のエラーを確認する
- [ ] 誤った接続情報でのエラーを確認する

## 学習確認

- [ ] HTTP接続失敗とDB接続失敗の違いを説明する
- [ ] `psql` での直接確認が切り分けに役立つ理由を説明する
