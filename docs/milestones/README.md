# マイルストーン詳細ファイルの運用

## 1. 目的

`docs/ROADMAP.md` は全体像だけを保持し、現在実行するマイルストーンの詳細は、このディレクトリに分離します。

未来のマイルストーン詳細を最初から作成しないことで、次を防ぎます。

- 実装前の過剰な計画
- 学習状況と合わない固定計画
- 使わないドキュメントの増加
- 計画作成そのものが目的になること

## 2. ファイル構成

```text
docs/milestones/
├── README.md
├── TEMPLATE.md
├── M0.md
└── M1.md  # M1開始時に作成する
```

ファイル名は `M<番号>.md` とします。

## 3. 作成タイミング

次のマイルストーン詳細は、現在のマイルストーンの通過条件を確認した後に作成します。

例:

```text
M0完了
  ↓
M0振り返り
  ↓
ROADMAPのM1を確認
  ↓
M1で必要な合成データと件数を確認
  ↓
既存データで不足する分だけ追加する方針を決める
  ↓
TEMPLATE.mdからM1.mdを作成
  ↓
M1の最初のサイクルをPROGRESS.mdへ設定
```

## 4. データ設計

マイルストーン開始時に、機能のサイクル分割と同時に、そのマイルストーンで必要な合成データを確認します。

- 実在する会社、設備、業務データは使用しない
- 既存の合成データで目的を満たせる場合は、新しいデータを追加しない
- 不足する場合は、必要件数、必要な特徴、期待する検索・更新結果を明記する
- 最初は固定データを優先し、大量データが必要になった時点でseedスクリプトを追加する
- ランダム生成する場合はseedを固定する
- 設備名、エラーコード、状態、文書の内容に矛盾がないことを確認する
- RAG評価では質問、期待文書、期待要素を対応付ける
- 将来のマイルストーンで使うデータを先回りして大量生成しない

## 5. サイクルの分割基準

1サイクルは、ユーザーが確認可能な1つの成果にします。

良い例:

- health APIがHTTP 200を返す
- PostgreSQLから1件のデータを取得する
- Reactに一覧を表示する
- 不正入力で422を返す

大きすぎる例:

- CRUD、検索、認証をまとめて作る
- RAGを完成させる
- AIエージェントを実装する

サイクルが次のいずれかに該当する場合は分割します。

- 主要概念が2つ以上含まれる
- 正常系を確認する前に複数ライブラリの導入が必要
- 変更対象が広く、失敗箇所を切り分けにくい
- 完了結果を一文で説明できない

## 6. サイクルに記載する内容

各サイクルには次を記載します。

- ユーザーから見える成果
- 学習目的
- なぜこの順序なのか
- 主な変更対象
- 使用する合成データと、そのデータが必要な理由
- データの再現方法と一貫性の確認方法
- 実装の大まかな流れ
- 受け入れ条件
- 異常系確認
- テスト
- 今回扱わないこと
- 完了後の理解確認

詳細なコマンドやコードは、実際にサイクルを開始するときにCodexが提示します。

## 7. サイクルの状態

次のいずれかを使用します。

```text
Not started
In progress
Blocked
Completed
Skipped
```

`Skipped` にする場合は理由を記録します。

## 8. サイクル完了時

1. 受け入れ条件を確認する
2. 異常系を最低1つ確認する
3. 自動テストまたは再現手順を残す
4. 学習した概念を一文で記録する
5. 未理解事項を `docs/PROGRESS.md` に移す
6. 次のサイクルをCurrentにする
7. 次に行う1ステップを更新する

## 9. マイルストーン完了時

1. マイルストーン通過条件をすべて確認する
2. ユーザーから見える動作を実演する
3. 処理経路を図または文章で説明する
4. 小さな仕様変更を1つ行う
5. 振り返りを記録する
6. 保留事項を整理する
7. `docs/ROADMAP.md` と `docs/PROGRESS.md` を更新する
8. 次のマイルストーン詳細を作る

## 10. Codexへの依頼例

```text
M1を開始します。

README.md、AGENTS.md、docs/ROADMAP.md、docs/PROGRESS.md、
docs/milestones/TEMPLATE.md、完了済みのM0.mdを確認してください。

M1の到達状態と通過条件を変えずに、現在の実装状態に合わせて
2〜5個の短いサイクルへ分割し、docs/milestones/M1.mdを作成してください。
M1で必要な合成データの件数、特徴、作成方法も必要最小限で定義してください。
実在する業務データは使用せず、未来のマイルストーン詳細やデータは先回りして作成しないでください。
```
